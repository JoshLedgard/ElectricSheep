The Long Tail

An assistant answer is a short pipeline: look something up, think, call a few tools. Change how long each step takes, run the tools one after another or all at once, and watch what happens to the typical request versus the slow ones.

⚗︎ Synthetic data. Every duration on this page comes from a seeded random model running in your browser. None of it is a measurement of any real product, model or service. The numbers show how the model behaves; they don't say how fast any real system is.

How the numbers are made

  1. A fixed, seeded sample. A small deterministic random generator (seed ) draws 5,000 synthetic requests. The same seed always gives the same page. New sample changes the seed.
  2. Each stage is lognormal. A stage with median m and variability σ takes m × eσ·z, where z is a standard normal draw. That gives a right-skewed shape: most calls land near the median and a few run long. With hiccup chance h, a stage independently stalls and takes 4× as long.
  3. Stages add up. request = retrieval + reasoning + tools. Sequential tools: tools = t₁ + t₂ + … + tₖ. Parallel tools: tools = max(t₁ … tₖ), because the answer waits for the last one.
  4. Percentiles by nearest rank. Sort the 5,000 totals. P50 is the 2,500th, P95 the 4,750th and P99 the 4,950th. A and B reuse the same z and hiccup draws (common random numbers), so comparisons aren't muddied by sampling noise.
  5. Tail amplification. If each task independently has a 5% chance of running past its own P95, then the chance that at least one of k parallel tasks does is 1 − 0.95k. At 4 tasks that's about 19%. At 12 it's about 46%. A rare event per task becomes a common one per request.
  6. What it leaves out. Real systems have queues, retries, timeouts, rate limits, caching and correlated slowdowns, where one busy dependency slows every task at once. None of that is modeled here. Use the lab to build intuition about shapes and ratios, not to predict real numbers.
