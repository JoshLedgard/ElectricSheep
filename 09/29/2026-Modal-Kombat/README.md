# Modal Kombat

## What it is

Modal Kombat is a self-contained 90-second desktop-defense game. Needy windows multiply across a fictional operating system; drag them into the Archive, build combos, and spend limited Pin, Merge, and Snooze tools before the desktop becomes unruly. It runs entirely in a browser with no server, package install, external assets, or network connection.

## Privacy-safe inspiration

Inspired by the generic craft of polished interfaces, dependable tools, and playful product prototypes. It does not represent or reproduce any real project, company, customer, person, or conversation.

## How to open

Open `index.html` in any modern browser, then press **Clock In**. It works with touch, mouse, trackpad, or keyboard.

## Controls

- **Drag:** grab any window and drop it on the yellow Archive dock.
- **Select:** tap or click a window to outline it, then use Pin or Snooze.
- **Pin:** freezes the selected window's expiry meter. Three uses per run.
- **Merge:** combines the two newest active windows into one. Three uses per run.
- **Snooze:** hides the selected window for five seconds. Three uses per run.
- **Pause:** pauses spawning, expiry, and the shift clock. Escape also pauses.
- **Keyboard:** `1`, `2`, and `3` activate Pin, Merge, and Snooze.
- **Replay:** finish the 90-second shift to earn a rank, then run it back.

## Why it was built

A utility interface is usually supposed to be calm and obedient. Modal Kombat flips that premise: the interface itself becomes the opponent, while familiar desktop actions become tactile game moves. The escalating spawn rate, expiring windows, limited tools, combo timing, sound cues, and final rank make it a compact arcade loop rather than a themed static page.

## Format choice

- **Lane:** Weird playable game / fake desktop-app artifact

This differs structurally from the recent screenshot-analysis tool, responsive music instrument, tactile timeline, and interface-deduction game.

## Privacy, mobile, and accessibility

The game contains only fictional generic UI copy and makes no network requests. It contains no real names, emails, phone numbers, addresses, financial data, credentials, private quotations, or personal details. The layout is designed for a 390px viewport without horizontal overflow, uses pointer events for touch and mouse, prevents page movement while dragging, provides 44px-class primary controls, supports keyboard shortcuts and Escape-to-pause, and honors reduced-motion preferences. Audio begins only after player interaction.
